# Registry Format

How mods reach players: **package sources**. A source is anything the launcher and CLI can turn into a
catalog of installable `.robotopiamod` packages. This page specifies the wire formats and shows how to host your own
source. The built-in official source initially contains release-generated first-party packages only; community
submissions are closed until registry governance is approved. Follow [PublishingYourMod.md](PublishingYourMod.md) for
the supported self-hosted workflow.

## Source shapes

A source URL (or local path) may point at any of three shapes:

| Shape | Recognized by | Use for |
|---|---|---|
| **Registry index** — `{ "formatVersion": 1, "mods": [...] }` | top-level `mods` array | the official registry and self-hosted registries (this page) |
| **VPM listing** — `{ "packages": { ... } }` | top-level `packages` key | Unity/VCC-style package listings (see [UnityVpm.md](UnityVpm.md)) |
| **Package directory** — a folder of `.robotopiamod` files | local directory path | zero-setup local/LAN sharing; the catalog is derived from the packages themselves |

Windows drive-letter paths (`C:\mods`) and `file://` URLs both work for local sources; remote sources use
`https://`.

Players add a source in the launcher under **Settings → Package Sources**, or from the CLI with
`robotopia add source <name> <url> [--id id]`. Developer projects do **not** consult the official registry
for `resolve`/`restore` by default — build steps stay offline-deterministic. Opt a project in explicitly:

```sh
robotopia add source "QuantumWorks Registry" https://furroxide.github.io/quantum-works/registry/index.json --id robotopia.official
```

(Run inside the project, or pass `--project <path>`.)

## The official registry

- Index: `https://furroxide.github.io/quantum-works/registry/index.json`.
- Ships in the launcher as the built-in source `robotopia.official` — it can be disabled, not deleted.
- Generated by CI:
  `robotopia registry index --repository furroxide/quantum-works --entries registry --changelogs mods`.
- First-party `.robotopiamod` files are immutable GitHub Release assets generated from the release BOM.
- Community entry files are validated for future format compatibility but are not included or automatically deployed.
- Authors distribute through self-hosted indexes until an ownership, review, revocation, and appeal policy explicitly
  reopens the official submission path.

## Index format (`formatVersion` 1)

```json
{
  "$schema": "https://raw.githubusercontent.com/furroxide/quantum-works/main/schemas/robotopia.registry-index.schema.json",
  "formatVersion": 1,
  "name": "QuantumWorks Mod Registry",
  "generatedAt": "2026-07-04T12:00:00Z",
  "sourceRepository": "https://github.com/furroxide/quantum-works",
  "mods": [
    {
      "manifest": { "…": "full robotopia.mod.json content" },
      "downloadUrl": "https://…/<id>-<version>.robotopiamod",
      "packageSha256": "<64 lowercase hex of the exact hosted bytes>",
      "changelog": "notes for the latest version",
      "origin": "first-party",
      "history": [
        {
          "version": "…",
          "downloadUrl": "…",
          "packageSha256": "…",
          "changelog": "…"
        }
      ]
    }
  ]
}
```

Rules:

- **One entry per mod id**, and that entry is the **latest** version; older versions live in `history`.
- `manifest` is the mod's full `robotopia.mod.json` content, inlined.
- `downloadUrl`: absolute `https`, or relative to the index location.
- `packageSha256`: 64 lowercase hex characters — the SHA-256 of the **exact hosted bytes**. Installs verify
  it, so the hosted file must never change (publish a new version instead).
- `origin`: `first-party` or `community`.

## Entry files (submission tooling; official intake closed)

The repository retains per-mod entry files at `registry/<id>.json`, filename = the **lowercase** mod id, so
append-only validation can be tested before official intake opens. `robotopia registry add-entry` can generate this
format for a self-hosted workflow, but changes to the repository's community entries are rejected while submissions
are closed.

```json
{
  "$schema": "https://raw.githubusercontent.com/furroxide/quantum-works/main/schemas/robotopia.registry-entry.schema.json",
  "formatVersion": 1,
  "id": "coolauthor.jetpack",
  "homepage": "https://github.com/coolauthor/jetpack",
  "versions": [
    {
      "version": "1.1.0",
      "downloadUrl": "https://…",
      "packageSha256": "…",
      "changelog": "…",
      "manifest": { "…": "full robotopia.mod.json, inlined" }
    }
  ]
}
```

- `versions` is **newest-first**.
- `manifest` is **required, inlined** in every version — index builds never download community packages.
- Existing version objects are immutable. Only a unique, strictly newer SemVer may be prepended; deletion, rename,
  reordering, or mutation of historical fields is invalid.

## Self-hosting a registry

Any static file host works — GitHub Pages, S3, nginx, a LAN share. No server code needed.

```sh
robotopia registry index --dir packages --output site/registry
```

- In `--dir` mode, `downloadUrl`s default to **bare filenames** — relative to the index location, which is
  correct when the packages sit beside `index.json`. Pass `--base-url <url>` to make them absolute (when
  packages are hosted elsewhere).
- `--include-prerelease` includes pre-release versions; `--entries <dir>` merges entry files in;
  `--changelogs <dir>` picks up per-mod changelogs (the official CI uses both).
- Upload the output (plus the `.robotopiamod` files, unless `--base-url` points elsewhere) and share the
  index URL. Players add it as a package source (see above).

For quick local testing, skip the index entirely and point a source at the folder of `.robotopiamod` files.

## How sources are consumed

- Registry mods **dedupe to one entry per id** across all sources — the highest version wins; on a version
  tie the bundled local source is kept.
- Remote installs **require the sha256 up front** and verify the downloaded bytes; downloads cap at
  **512 MB**.
- A failing source degrades gracefully — the launcher shows per-source status and the other sources keep
  working.

## Forward compatibility

- `formatVersion` 1 is **additive-only**: new optional fields may appear at any time, and consumers must
  ignore fields they don't recognize.
- A registry index must **never** gain a top-level `packages` key — that key makes the document parse as a
  VPM listing.
- Breaking format changes ship at a **new path** (a new index URL), never as an in-place mutation of an
  existing index.
