An administrator prepares one private `sandbox-local-lane-admission-v1` JSON record per reservation. No ready-to-sign placeholder approval is checked in. Its exact fields are:

- `schemaVersion`: integer 1; `kind`: `sandbox-local-lane-admission-v1`; `lane`: `editor` or `game`; `sourceRevision`: actual reviewed 40-character lowercase Git SHA.

- For an explicitly staged game source snapshot, also include `sourceWorkspaceSha256`, the lowercase SHA-256 of its reviewed private `sandbox-source-workspace-v1` input. This extra field is required only with `-SourceWorkspace`; it is rejected in the ordinary Git mode. Editor admission continues to require its reviewed Git checkout.
- `devices`: unique entries with exactly `kind` and `id`. Display, keyboard and mouse are mandatory; game execution also requires an approved audio-output device. Supported optional kinds are microphone and gamepad. Reserve actual identifiers, not guessed default devices.

## Failure, interruption and recovery

SIGINT, output overflow and timeout first write a challenge-bound private `broker-cancel.json`. The broker receives twenty seconds for cooperative input/fixture cleanup before the original broker process can be force-terminated. Forced termination never proves cleanup; a separate operator recovery remains necessary. Acknowledgement and package polling use the remaining overall budget, and the Editor runner uses one total deadline across its build and both Editor processes.

Before invoking a local runner, the wrapper writes `sandbox-recovery-required.json` beneath the private root while holding the machine mutex. It clears only that exact marker after the runner confirms cleanup. Raw run evidence remains retained. Failed scenario assertions may release the reservation when cleanup is confirmed; unknown cleanup, an abandoned reservation, ambiguous output or verifier refusal leaves recovery pending.

1. The named operator stops further lane attempts and preserves the first failure, run directories, admission, process receipt, transcript and original captures. Do not retry over an existing run or auto-accept new baselines.
2. Confirm input release and inspect the original owned Editor/game process using its recorded executable and native start identity. Never kill whichever process happens to reuse its PID, kill all Unity/game processes or delete a layout with unconfirmed ownership.
3. Restore or quarantine the isolated QA fixture/save/device state using the reviewed recovery procedure. Do not touch normal-user saves or broad profile directories.
4. Record the actual recovery result privately. Remove the exact recovery marker only after separate operator authorization and verified process/input/fixture cleanup; the wrapper offers no automatic recovery bypass.
5. Obtain a new bounded reservation/run ID and preserve the prior result. If foreground, display, audio device, source bytes or reviewed baselines changed, update the relevant reviewed inputs before retrying.

A local development result does not close P0-GAME-01, authorize governance changes or replace actual reviewer approval.
