# TopiaForge UI brand bundle builder

This tiny Unity project builds `topiaforge-ui.bundle` — the brand AssetBundle
(TextMeshPro font assets + brand sprites) that `TopiaForge.Mods.UnityUi` embeds into its
DLL and loads at runtime. It also doubles as an editor harness for visual QA of the kit.

## Editor version rule (hard requirement)

The Robotopia player is **Unity 6000.0.23f1 (1c4764c07fb4)**. AssetBundles must be
serialized by the same editor version as the shipped player. Headless install via the Unity Hub CLI:

> **Artifact status:** the tracked bundle and embedded provenance are generated by the pinned
> 6000.0.23f1 editor and contain the Audiowide and Quicksand assets. Re-run the builder whenever the source
> font assets change so the binary and both provenance manifests remain synchronized.

```sh
# Windows
& "$env:ProgramFiles\Unity Hub\Unity Hub.exe" -- --headless install --version 6000.0.23f1 --changeset 1c4764c07fb4
# macOS / Linux
unityhub -- --headless install --version 6000.0.23f1 --changeset 1c4764c07fb4
```

`topiaforge unity build-ui-bundle` auto-detects eligible editors and hard-fails on
anything else.

## Prerequisites on macOS/Linux

- The bundle currently targets `StandaloneWindows64`, so the editor needs the **Windows Build Support (Mono)**
  module installed via Unity Hub. The native macOS runtime is supported, but it may use TopiaForgeUi's documented
  OS/game-font fallback when this Windows-targeted brand bundle cannot load.
- The editor must have an activated Unity license (batchmode fails without one).
- Headless Linux boxes need a display for the build (no `-nographics` — TMP font baking
  needs `Shader.Find`); use `xvfb-run` if there is no desktop session.
- `git lfs` must be installed to check out and commit the bundle.

## Font baking

The build script bakes the static SDF TMP font assets itself (idempotent — an existing
committed `Assets/FontAssets/*.asset` is reused after its derivative object/family
names are normalized; delete it only to re-bake the atlas):

- `TopiaForge Body Medium SDF` — Quicksand Medium (500), for body, label and caption
  text. 1024×1024, SDFAA, padding 9, static; ASCII + Latin-1 Supplement + Latin
  Extended-A + typographic punctuation.
- `TopiaForge Body SDF` — Quicksand Light (300), the variable font's default instance,
  for Quicksand text larger than body text: headings and numerals. Same settings.
- `TopiaForge Display SDF` — Audiowide, 512×512, same settings (display headings).
- Bold renders via TMP faux-bold over each style's face; no bold asset ships.

Unity imports only a variable font's default instance, so `TopiaForge Body Medium SDF`
is baked from `Assets/Fonts/TopiaForgeBody-Medium.ttf`, a static Medium instance that
`make_body_medium_font.py` writes with fontTools (`pip install fonttools==4.65.0`, then
`python make_body_medium_font.py`). The script accepts only the upstream Quicksand
release recorded in `THIRD_PARTY_NOTICES.md` and writes the same bytes on every run.
Run it again only when that source font changes.

A re-bake is reproducible byte for byte. Unity gives a new asset a random GUID, and its
material and atlas pages random local ids, so the builder writes each freshly baked SDF
again with the GUID pinned in `Assets/Editor/UiBundleReproducibleAssets.cs` and fixed
sub-asset ids. To re-bake an SDF, delete its `.asset` and `.asset.meta` and build. A new
SDF needs a pinned GUID there first.

With an unchanged source font, a re-bake of `TopiaForge Body Medium SDF` matches the
committed files. `TopiaForge Body SDF` and `TopiaForge Display SDF` were baked before
the ids were pinned, and the Body SDF from an earlier copy of the Quicksand font, so the
first re-bake of either changes its `.asset` and the bundle; later re-bakes match.

Every font-asset material stays on TMP's `TextMeshPro/Mobile/Distance Field` shader
(`Assets/TextMesh Pro/Shaders/TMP_SDF-Mobile.shader`) — building the bundle pulls the
shader in as a dependency, which is the in-game safety net. That vendored shader omits
the `#pragma enable_d3d11_debug_symbols` line TMP ships with: on Windows the directive
compiles it unoptimized, with debug data that changes on every compile and records
absolute editor paths, so the bundle stops being reproducible. Keep it out if the TMP
essentials are ever re-imported.
Commit the baked `.asset` files (+ `.meta`) together with the rebuilt bundle.

## Building the bundle

From `apps/topiaforge_cli` (or anywhere inside the repo):

```sh
dart run bin/topiaforge.dart unity build-ui-bundle             # auto-detects an eligible editor
dart run bin/topiaforge.dart unity build-ui-bundle --unity "C:\Program Files\Unity\Hub\Editor\6000.0.23f1\Editor\Unity.exe"
dart run bin/topiaforge.dart unity build-ui-bundle --rebuild   # also rebuilds TopiaForge.Mods.UnityUi
```

Or in-editor: **TopiaForge → Build UI Bundle**.

The build stamps provenance into `Assets/UiBundleManifest.json`, verifies the required
assets are labeled `topiaforge-ui`, builds LZ4 for StandaloneWindows64, and copies the
result to `src/TopiaForge.Mods.UnityUi/Assets/topiaforge-ui.bundle` (+ a SHA256
provenance json). Rebuild the .NET solution afterwards so the embedded resource updates.

## Lifecycle smoke

After the Release runtime/UI assemblies exist, run
`TopiaForge.UiLifecycleSmoke.Run` in batch mode with
`-robotopiaManagedDir <game Data/Managed>` and
`-topiaforgeLifecycleEvidence <output.json>`. The harness first loads the exact
Robotopia Memory/Buffers/Unsafe profile dependencies, the shipped
Metadata/Immutable pair, Abstractions, Worlds, and then UnityUi. It executes the
metadata-only package validator under Unity Mono before entering play mode. It
then creates and disposes 16 hosts with windows, modals, hotkeys, tweens, profile
changes, and clears, failing unless canvases, allocator capacity, cursor leases,
dismiss entries, hotkeys, theme subscriptions, and tweens all return to baseline.
Success writes machine-readable evidence; the protected Unity workflow verifies
and uploads it. This caught and now guards Unity fake-null component lookup
regressions.

`*.bundle` is Git LFS-tracked (see `.gitattributes`).
