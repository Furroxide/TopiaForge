# TopiaForge 0.1.0-rc.1 — early prerelease

TopiaForge 0.1.0-rc.1 is an early prerelease of the modding toolchain toward
`0.1.0`. It is intended for maintainers, mod authors, and players willing to
test installation, repair, authoring, packaging, and game integration. A 0.x
line makes no cross-minor compatibility promise and is not the recommended
build for unattended or long-lived installations. Back up saves and profiles
before testing, and use a separate game installation for experiments.

## What to test

- Install, repair, diagnose, and launch Robotopia through the desktop launcher.
- Create, restore, test, pack, validate, and install a mod using the packaged CLI
  and each of the seven templates on a clean machine.
- Exercise profiles, dependency planning, load ordering, package recovery, and
  the thirteen bundled first-party packages.
- Report platform-specific launch, signing, accessibility,
  focus, scaling, or overflow problems with enough detail to reproduce them.

## Download and verification

Download the complete Windows archive and `SHA256SUMS` from this release. Check
the archive against `SHA256SUMS` before extracting it, keep the archive layout
intact, and run `topiaforge doctor --strict` before the first game launch.

RC1 contains a Windows x64 archive only. Neither a Linux nor a macOS archive
is part of `0.1.0-rc.1`.

Linux support remains in the source tree, but native Proton acceptance has not
been completed on a host with working GPU Vulkan support. No future release
version is promised for Linux or macOS distribution.

The Windows launcher, CLI and GameCompat extractor are intentionally unsigned.
Windows may display an
unrecognized-publisher or SmartScreen warning; no Authenticode publisher identity
is claimed. Signed update metadata and published checksums verify different
properties and do not supply Windows code signing. Inspect the release's
verification evidence before deciding whether to run it.

GitHub is the verifier and publisher of the administrator-built bytes, not
their builder.
All users should verify `topiaforge-update-v1.json` against its Ed25519 sidecar;
the initial trusted key is `ed25519:26229e3d2b54e81c`. Do not install an asset
whose checksum, signed metadata, recorded platform trust, or attestation does
not match the release.

## Highlights

- A BepInEx game runtime behind Unity-free core and specialist SDK contracts.
- A desktop launcher for detection, install and repair, profiles, dependency
  planning, diagnostics, and deterministic launch orchestration.
- A signed, confirmation-only whole-package updater for future stable/beta
  releases, with bounded downloads and extraction, an external atomic-swap
  helper, startup health handshake, rollback, and interruption recovery.
- A CLI and seven templates that work without a source checkout or Unity
  installation for ordinary code mods.
- Thirteen first-party packages plus two VPM packages in one deterministic
  ecosystem payload; UiGallery remains source-only.
- An F5 Creator workbench inside the Sandbox mod: safe catalogs, reversible scene
  editing, RobotKit personalities and conversations, and bounded local visual event
  projects. The standalone Creator Tools package no longer ships — the workbench
  moved into Sandbox now that the Robotopia Creator covers scene authoring.
- Opposite Day, an opt-in gameplay mod that privately inverts the dominant actionable
  intent of native and RobotKit-backed robot plans while preserving valid engine actions.
- Frozen public API baselines, strict package validation, generated local SDK
  feeds, and runner-neutral testing support.

## Known scope limits

- The SDK is consumed from this release archive's local package feed. TopiaForge
  publishes to no external package ecosystem: there is no nuget.org, pub.dev, or
  hosted VPM listing for `0.1.0-rc.1`.
- Robotopia support is build `2409` only. Mods whose declared range extends past
  that build are declaring intent, not tested coverage.
- The launcher UI is English only. There is no localization support yet.
- UGC live sync is retired in this line. Its companion Unity package and the
  `topiaforge mod add ugc` module are gone; the Robotopia Creator covers that ground.

## Multiplayer API preview

This candidate includes the Unity-free `TopiaForge.Mods.Multiplayer` authoring
contract and source generator. Authors get typed commands, bounded codecs,
snapshot-backed state, replicated objects, owner prediction with rollback and
replay, presentation events, admission metadata, and a deterministic multi-peer
test rig. The first-party provider supplies standalone loopback behavior in
Robotopia.

Live networking, dedicated Robotopia hosting, package auto-download, and an
anti-cheat guarantee are not included. Mods opt in explicitly through Manifest
V6 and the multiplayer module. Omitting `multiplayer` declares a standalone-only
package. See [Manifest V6](https://github.com/Furroxide/TopiaForge/blob/v0.1.0-rc.1/docs/ManifestV6.md).

## Migration from unreleased builds

This candidate intentionally breaks the unreleased 0.1.x SDK surface; no public
compatibility promise was made for those builds. First-party mods and templates
have migrated together.

- Manifest V6 is the current authoring contract. V3, V4 and V5 are rejected by
  current readers. Run `topiaforge migrate-manifest` to normalize an unreleased
  manifest; missing gameplay declarations require explicit author input.
  Migration preserves untouched values and refuses malformed input before
  writing. Incomplete gameplay declarations require the explicit stub workflow;
  those stubs remain invalid until completed. Optional world requirements stay
  optional. Use V6 templates for new packages.
- `IModContext.Player` and `IPlayerService` are now `LocalPlayer` and
  `ILocalPlayerService`.
- `Storage` and `IModStorageService` are now `LocalStorage` and
  `ILocalModStorageService`; the unsupported story-flag persistence facade was
  removed.
- `SceneLoadEvent.IsAuthoritativeReplacement` is now `IsWorldReplacement`.
- To opt in to multiplayer, run `topiaforge mod add multiplayer`, restore, then
  run `topiaforge mod sync multiplayer` and commit the generated contract lock.

## Known limitations

Robotopia build `2409` is the only supported game build for this candidate.
Prerelease launchers check the beta channel by default after a persisted
cooldown, but never install silently; a manual download remains available for
unsupported layouts. Custom worlds remain Windows-only in this candidate, and
mods execute arbitrary code with the game process's access. Install only packages
and authors you trust; capability declarations provide disclosures rather than a
security sandbox. Linux and macOS packaging remain future-platform capabilities
and are not distributed here.

First-party remote AI, player-token use, microphone capture and speech-to-text
default off. Enabling remote features can send prompts, conversation data or
recorded speech to an external service using the player's token. Read the
[privacy and capability inventory](https://github.com/Furroxide/TopiaForge/blob/v0.1.0-rc.1/docs/PrivacyAndCapabilities.md)
before opting in.

A later Windows update must reuse the embedded update key and demonstrate a real
upgrade from the installed `rc.1` candidate plus forced rollback. Linux packaging
requires separate platform approval, native isolation and acceptance evidence.

Support is best effort, with no response-time or long-term-support guarantee;
see [support guidance](https://github.com/Furroxide/TopiaForge/blob/v0.1.0-rc.1/SUPPORT.md).
Use [GitHub issues](https://github.com/Furroxide/TopiaForge/issues) for reproducible
defects and include a redacted diagnostic bundle. Report vulnerabilities privately
as described in [SECURITY.md](https://github.com/Furroxide/TopiaForge/blob/v0.1.0-rc.1/SECURITY.md); do not
put secrets, account data, proprietary game assemblies, or unpatched security
details in a public issue.
