# TopiaForge 1.0.0-rc.1

TopiaForge 1.0.0-rc.1 is the first public release candidate for the V1 modding
toolchain. It is intended for maintainers, mod authors, and players willing to
test installation, repair, authoring, packaging, and game integration before
the stable 1.0.0 release. It is not yet the recommended build for unattended or
long-lived installations.

## What to test

- Install, repair, diagnose, and launch Robotopia through the desktop launcher.
- Create, restore, test, pack, validate, and install a mod using the packaged CLI
  and each of the seven templates on a clean machine.
- Exercise profiles, dependency planning, load ordering, package recovery, and
  the fifteen bundled first-party packages, including an opt-in Creator profile.
- Report platform-specific launch, signing, notarization, Proton, accessibility,
  focus, scaling, or overflow problems with enough detail to reproduce them.

## Download and verification

Download one complete platform archive and `SHA256SUMS` from this release. Check
the archive against `SHA256SUMS` before extracting it, keep the archive layout
intact, and run `topiaforge doctor --strict` before the first game launch.

Windows builds must have a valid Authenticode signature and timestamp. The
macOS app must pass Gatekeeper validation and show a stapled notarization ticket.
Linux users should verify the checksum and the GitHub build-provenance
attestation. Do not install an asset whose checksum, signature, notarization, or
attestation does not match the release.

## Highlights

- A BepInEx game runtime behind Unity-free core and specialist SDK contracts.
- A desktop launcher for detection, install and repair, profiles, dependency
  planning, diagnostics, and deterministic launch orchestration.
- A CLI and seven templates that work without a source checkout or Unity
  installation for ordinary code mods.
- Fifteen first-party packages plus three VPM packages in one deterministic
  ecosystem payload; Creator Tools is installed disabled and UiGallery remains source-only.
- A shared F5 Creator workbench for the Sandbox and optional standalone Creator Tools:
  safe catalogs, reversible scene editing, RobotKit personalities and conversations,
  and bounded local visual event projects.
- Opposite Day, an opt-in gameplay mod that privately inverts the dominant actionable
  intent of native and RobotKit-backed robot plans while preserving valid engine actions.
- Frozen public API baselines, strict package validation, generated local SDK
  feeds, and runner-neutral testing support.

## Multiplayer API preview

This candidate includes the Unity-free `TopiaForge.Mods.Multiplayer` authoring
contract and source generator. Authors get typed commands, bounded codecs,
snapshot-backed state, replicated objects, owner prediction with rollback and
replay, presentation events, admission metadata, and a deterministic multi-peer
test rig. The first-party provider supplies standalone loopback behavior in
Robotopia.

Live networking, dedicated Robotopia hosting, package auto-download, and an
anti-cheat guarantee are not included. Mods opt in explicitly through Manifest
V5 and the multiplayer module.

## Migration from unreleased builds

This candidate intentionally breaks the unreleased 0.1.x SDK surface; no public
compatibility promise was made for those builds. First-party mods and templates
have migrated together.

- Manifest V4 is retired. Run `topiaforge migrate-manifest --project .`;
  omitting `multiplayer` keeps a V5 mod standalone-only.
- `IModContext.Player` and `IPlayerService` are now `LocalPlayer` and
  `ILocalPlayerService`.
- `Storage` and `IModStorageService` are now `LocalStorage` and
  `ILocalModStorageService`; the unsupported story-flag persistence facade was
  removed.
- `SceneLoadEvent.IsAuthoritativeReplacement` is now `IsWorldReplacement`.
- To opt in to multiplayer, run `topiaforge mod add multiplayer`, restore, then
  run `topiaforge mod sync multiplayer` and commit the generated contract lock.

## Known limitations

Robotopia build `2309` is the only supported game build for this candidate.
Launcher upgrades remain manual, custom worlds remain Windows/Proton-only, and
capability declarations are disclosures rather than a security sandbox. Native
macOS supports the launcher and runtime package, but not custom-world loading.

Use GitHub issues for reproducible defects and include a redacted diagnostic
bundle. Report vulnerabilities privately as described in `SECURITY.md`; do not
put secrets, account data, proprietary game assemblies, or unpatched security
details in a public issue.
